# Лаборатория сайта: операции и сценарии (v1, read-only)

## Зачем

Это простой штатный способ для ChatGPT и оператора исследовать разные рецепты создания сайта **без изменения Rust-кода после каждой гипотезы**. Здесь только три понятия:

1. **Инструмент** — версия операции, владелец, типы входов/выходов, эффекты и готовность. Каталог определяется установленными доверенными Rust-владельцами; наличие контракта не доказывает, что API доступен.
2. **Рецепт** — редактируемый JSON: источники с заявленной provenance, последовательность шагов, типизированные связи и необязательные `after`. Никаких Task Queue, секретов, провайдерских URL или динамического кода.
3. **Проверка** — детерминированная валидация и план-хеш через существующий `operation_protocol`. Сравнение двух рецептов показывает только **структурные различия**, не результат SEO-эксперимента.

Команды штатного бинарника `cli_tools` (запускать из корня репозитория):

```bash
cargo run --manifest-path app/rust/Cargo.toml -p cli_tools -- site-lab tools
cargo run --manifest-path app/rust/Cargo.toml -p cli_tools -- site-lab check --recipe-file docs/examples/site_lab_recipe_v1.json
cargo run --manifest-path app/rust/Cargo.toml -p cli_tools -- site-lab diff --first-file docs/examples/site_lab_recipe_v1.json --second-file docs/examples/site_lab_recipe_v1_alternative.json
```

Оба примера используют одни и те же задекларированные источники. Во втором `editorial` ждёт `canonicalize`; можно проверить, как это меняет зависимости. Это **не A/B-тест с трафиком**.

## Что показывает результат

- `valid_preview_only`: контрактный граф корректен, показаны `plan_hash` и `ordered_steps`.
- `steps_requiring_owner_admission`: операции с эффектами; в предварительном просмотре они допустимы **только как схема**, не как право вызвать провайдера.
- `source_authentication: not_verified`, `execution: not_started`: данные не загружались, Temporal не запускался, внешние эффекты не выполнялись.
- `invalid`: код проблемы, текст и `next_action`; завершение команды с кодом 2. Размер JSON ограничен 256 KiB, неизвестные поля запрещены.
- `structural_comparison_only`: проверены две структуры с объявленными источниками; результатов ранжирования, конверсии и поведения пользователей пока нет.

## Расширение возможностей

Чтобы подключить Voyage AI, Qdrant, Neo4j, Google Search Console, Google API, DataForSEO, аналитические источники спроса или любого нового поставщика:

1. Владелец провайдера оформляет типизированные операции и версии схем (`OperationContract`), маркирует побочные эффекты, инвалидации и правила идемпотентности. Контракты поступают **в доверенный каталог** через адаптер владельца, не из пользовательского JSON.
2. Лаборатория автоматически отображает новые операции. Существующие рецепты продолжают привязываться к своим версиям; пользователь может редактировать связи и проверять гипотезы.
3. Для *реального* запуска требуется независимый operator admission, проверенная provenance и эффект-владелец со своим маршрутом/секретами, idempotency/receipt fence. Единственный исполнитель production-графов остаётся за Temporal, без второй очереди или нового самодельного DAG-движка.
4. Затем появляются сравнение фактических run_id, диагностика по шагам, просмотр результатов и SEO-метрики. Они **ещё не реализованы** данной read-only командой.

Нельзя создавать «готовые» операции в интерфейсе только потому, что библиотека провайдера существует в репозитории: прежде нужен честный контракт владельца и его допуск. Не нужно создавать ещё один Temporal DAG, служебный процесс или дублирующую базу сценариев ради этой лаборатории.

## Следующий полноценный продуктовый срез

- Унифицированная выдача каталога/preview/check через уже штатный native API/MCP поверх **того же** `site_lab` без нового валидатора; понятная диагностика и схемы для ChatGPT.
- Доверенная регистрация доступных provider operations у их реальных владельцев. Отдельно `available to compose` и `ready to execute`.
- Старт **прошедшего admission** рецепта через существующий Temporal путь, сравнение реальных run_id и метрик качества/спроса, инструментальные evidence/trace.
- Простое представление: «Инструменты → Рецепт → Проверить → Запустить → Сравнить»; скрыть технические хеши до раскрытия диагностики.
